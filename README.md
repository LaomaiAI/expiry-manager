# 到期管理 - 再也不扔过期东西

一句话痛点：东西过期了才发现，扔掉的都是钱；现有的 App 全要一件件手动填，填两天就放弃了。
在线演示：https://laomaiai.github.io/expiry-manager/

## 它是做什么的

到期管理是一个手机优先的保质期管理应用，帮你记清家里食品、药品、保健品、日化用品、厨房用品、母婴及宠物的到期日，快过期时一眼就能看到。分类是六大类、50 多个小类，每个小类都有参考保质期，未开封和开封后分开写。
核心就一个差别：零录入。拍一张包装照片就能识别保质期，扫一下条码就能查到商品名，再按分类的参考保质期推算到期日。实在识别不出来，还可以手动填，也可以从清单打勾批量加入。

## 为什么做它

证据：2026 年 8 月，小红书上一条到期管理 App 的帖子有 304 个赞、1338 条评论排队领会员；2022 年知乎上一个问“怎么管理保质期”的问题，至今有 111 个收藏；2026 年 8 月一个月里就有 4 款同赛道新品上线。需求是真实的。
缺口：现有的 App 全是手动一件件填，录入是最大的流失点；大多 iOS 优先，安卓选择少；老产品说下架就下架，用户怕数据跟着陪葬。
新做法：扫码或拍保质期自动录入 + 安卓可装 + 数据随时能导出。不做账号，不做云端，数据只在你手机里。

## 四种添加方式

1. 拍照识别保质期：拍包装上印的日期，手机端 OCR 识别后列出候选日期，你点一个确认。包装上常印的是“生产日期 + 保质期 X 个月”，这种也会自动推算出到期日。
2. 扫码查商品：打开摄像头扫条码，食品从公开的 OpenFoodFacts 数据库查商品名，日化用品从同系列的 OpenBeautyFacts 查，查不到就回落到手动加参考表，不编造数据。药品和保健品不做扫码查询，只走手动。扫不出来可以上传条码照片，或手动输入条码数字查询。
3. 从清单批量添加：厨房常备、家庭药箱、浴室日化、母婴四组清单，打勾要加的物品，参考保质期已经按今天推算好；没有参考值的补填包装日期，都填好一并加入。
4. 手动添加：名称、分类、保质期、购买日期、数量、备注，填完保存。

## 参考保质期说明

参考保质期表分六大类、50 多个小类，例如鲜牛奶 7 天、鸡蛋 30 天、大米 365 天。参考值按公开食品安全指南的常见区间整理，只用来在没有印刷日期时帮你推算。表里每个小类都写明了未开封和开封后的区别，例如食用油未开封 18 个月、开封后 3 个月，化妆品未开封 3 年、开封后按 PAO 6 或 12 个月。
两条底线写在前面：包装上印的实际日期永远为准；药品和没有通用参考值的分类没有参考值，必须按包装日期填写。参考值不是承诺，表里每个分类都写明了依据和适用条件。

## 清单预设

四组清单：厨房常备（12 件）、家庭药箱（10 件）、浴室日化（12 件）、母婴（10 件）。点“从清单添加”，打勾要加的物品，带默认分类和按今天推算的参考保质期；药品这类没有参考值的，要补填包装上的日期，都填好才能一并加入。清单里的日期都是推算值，加入后请按包装日期核对。

## 开封后有效期

日化用品和眼药水这类东西，开封那天起就开始倒计时。填了开封日期后，到期日按开封日期加开封后月数算（日化默认 6 个月，可改；眼药水 1 个月，面膜和香皂这类一次用完的东西不算），再和包装上印的日期取较早者，卡片上会标明是哪一个决定的。没有填开封日期时，只按包装日期算。

## 安装与使用

这是一个 PWA（渐进式网页应用），不用去应用商店下载，不用注册账号。
1. 用安卓手机浏览器打开在线演示地址。
2. 浏览器菜单里选“添加到主屏幕”，以后点图标就能像 App 一样打开。
3. 点“添加物品”，拍照、扫码或手动添加。数据保存在手机浏览器里。

本地开发：
```bash
npm install
npm run dev
npm test
npm run build
```

## 为什么先做 PWA，不做小程序

微信小程序需要用个人微信账号认证，每次认证 30 元，而且账号要登到开发者的服务器上。PWA 不用账号、不用花钱、不用过审，任何手机浏览器打开就能装到主屏幕，功能上已经够用。所以 v1 先做 PWA，小程序以后再说。

## 数据与隐私

所有数据只存在你这台手机浏览器的 localStorage 里，不上传、不注册、不登录、不统计。随时可以导出 CSV 或 JSON 带走，也能从 JSON 文件导入回来。清掉浏览器数据会一起清掉物品，导出备份后再清空更稳妥。

## 确定性说明

这个应用是 100% 代码，没有用到任何大模型。
- 日期识别、紧急程度分级、保质期推算、CSV 导出，全部是本地代码规则，输入相同、结果相同。
- 三处用到网络：扫码查商品名走 OpenFoodFacts（食品）和 OpenBeautyFacts（日化用品）公开接口（免 key），OCR 首次使用要联网下载识别数据（约 10 MB，之后浏览器缓存）。断网时这几项不可用，手动添加永远可用。
- 测试见 src/lib/*.test.ts（Vitest），每次推送都会跑一遍。

## 还没在真机上验证的部分

这个版本是在 Linux 云电脑上开发的，npm 安装、构建、测试、网页预览都已验证通过。OpenBeautyFacts 的接口本身已用 curl 实测通（查到一条真实洗发水商品）。但以下几项只能在真手机上验证，本机测不了：摄像头扫码、拍照 OCR 的识别率、真实日化条码在两个数据库里的覆盖率、安装到安卓主屏幕后的表现。README 里写“已验证”的只有本机跑过的部分，其余以真机实测为准。
